GRAFT: Graph Retrieval-Augmented Fine-Tuning

A deep dive into my journey of building a highly optimized, local-first GraphRAG architecture for complex competitive programming and algorithmic data synthesis.

What is GRAFT?

Standard Vector RAG (Retrieval-Augmented Generation) is great, but it often fails at global synthesis because it retrieves isolated chunks of information. If you ask a complex algorithmic question, standard RAG might just pull disconnected paragraphs.

To solve this, I built GRAFT. It replaces naive semantic chunking with a Hierarchical Community Knowledge Graph. By combining this graph structure with 4-bit LoRA fine-tuning on a Qwen 3B model, and orchestrating it all through a Map-Reduce agentic pipeline, GRAFT achieves a mathematically proven 42.7% Head-to-Head Win Rate over standard Vector RAG on complex synthesis tasks.

Key Achievements

  • Hardware Optimized: Entire pipeline runs locally on a standard 4GB VRAM laptop GPU using 4-bit NormalFloat (NF4) quantization.
  • Rigorous Benchmarking: Automated LLM-as-a-Judge evaluation suite using DeepSeek-V4-Flash.
  • Diversity & Comprehensiveness: Achieved a 52.1% win rate in diversity and 50.0% in comprehensiveness against baselines.

The Architecture & Theory

Building GRAFT wasn't just about plugging APIs together. It involved a rigorous, 5-phase theoretical implementation.

1. Knowledge Extraction & Community Detection

First, I extracted 4,500+ text nodes from top competitive programming sources. Instead of dumping this into a Vector DB, I used DeepSeek-V4-Flash to extract core entities and relationships. Then, using the Leiden Algorithm on a NetworkX graph, the system detected dense hierarchical clusters, aggregating isolated nodes into 338 mathematically bounded algorithmic communities.

2. RAFT (Retrieval-Augmented Fine-Tuning)

To teach the 3B model how to read and synthesize dense community summaries, I utilized RAFT. I generated a highly specific Instruction-Tuning dataset in ChatML format and fine-tuned unsloth/qwen2.5-3b-instruct using LoRA (Low-Rank Adaptation) at Rank 16. This allowed the model to deeply understand the graph context without suffering from catastrophic forgetting.

3. Agentic Orchestration with LangGraph

At query time, a LangGraph StateMachine routes the user query. It retrieves the top 5 communities from a FAISS index, reranks them using a CrossEncoder (ms-marco-MiniLM-L-6-v2), and finally injects the optimized context into the 4-bit Qwen model to yield the final algorithmic response.

Bonus: Hosting This Project on GitHub Pages

If you're wondering how to host a project portfolio or a blog just like this one, it's easier than you think! I noticed URLs like toshit3q34.github.io/Selftape-AI which strongly suggests a GitHub Pages site.

The standard pattern for these sites is:
https://<github-username>.github.io/<repository-name>/

How to make one yourself

  1. Create a GitHub repository

    For example, name it my-portfolio.

  2. Add your website files

    At minimum, create an index.html file:

    <!-- index.html -->
<!DOCTYPE html>
<html>
<head>
    <title>My Website</title>
</head>
<body>
    <h1>Hello World!</h1>
</body>
</html>

    Push these files to your GitHub repository.

  3. Enable GitHub Pages

    In your repository, go to: Settings → Pages.

    Under Build and deployment, set:

    • Source: Deploy from a branch
    • Branch: main
    • Folder: /(root)

    Hit Save.

  4. Wait a minute or two

    GitHub will publish the site automatically. Your website will appear at:
    https://yourusername.github.io/my-portfolio/ for a project repository.

Want a Root URL?

Instead of yourusername.github.io/my-portfolio, if you want your site directly at the root, create a repository named exactly: yourusername.github.io.

Then your site becomes https://yourusername.github.io with no repository name in the URL.
