GRAFT Framework

Graph Retrieval-Augmented Fine-Tuning

A comprehensive theoretical breakdown bridging structured knowledge extraction and domain-specific alignment.

1. The Core Paradigm: Addressing the Limitations of Vector RAG

Traditional Retrieval-Augmented Generation (Vector RAG) relies on a top-$k$ retrieval paradigm. The system chunks documents, generates dense vector representations using text embeddings, and fetches the most semantically close pieces based on a user query.

While highly efficient for localized fact retrieval, this architectural setup introduces structural vulnerabilities when applied to complex knowledge tasks:

  • The Multi-Hop Reasoning Deficit: Multi-hop questions require intersecting disjoint pieces of evidence scattered across independent documents. Vector RAG often leaves out critical intermediate steps because it fetches contexts independently based on their direct similarity to the raw query, failing to follow a logical path.
  • The Global Summarization Bottleneck: For sensemaking or global queries (e.g., "What are the main themes across this document collection?"), Vector RAG inherently breaks down. These questions require a global holistic synthesis rather than specific fact retrieval. Vector RAG cannot fit an entire millions-of-tokens corpus into an LLM's finite context window, and choosing a subset of top-$k$ localized text chunks completely misses the broader thematic patterns.

2. Theoretical Pillar 1: GraphRAG & Global Sensemaking

To solve the global sensemaking limitation, GRAFT utilizes structural data abstractions via a Knowledge Graph Index. Instead of treating a corpus as a disjoint set of text chunks, GraphRAG converts it into a network of explicit semantic concepts.

A. Graph Construction Workflow

  • Entity & Relation Extraction: Source documents are segmented into overlapping text chunks. A frontier LLM (e.g., GPT-4o) executes abstractive summarization to extract named entities (nodes), their relationships (edges), and corresponding contextual descriptions.
  • Weighted Graph Assembly: Extracted components are mapped into an undirected, weighted graph. The structural prominence of relationships is preserved mathematically: duplicate relationship mentions across text chunks are aggregated into edge weights ($W_{e}$) representing the frequency of occurrence.
  • Claim Aggregation: Factual claims—verifiable statements mapping dates, events, or specific actions to entities—are extracted concurrently to serve as high-fidelity semantic grounding for downstream retrieval.

B. Topological Modularity: Community Detection via the Leiden Algorithm

A massive knowledge graph can quickly become a complex, unreadable "hairball" if queried globally without structure. To make this scalable, GraphRAG leverages the graph's inherent modularity. GRAFT applies the Leiden Algorithm to partition the graph index into hierarchical, nested communities of tightly knit nodes. The algorithm optimizes community partitions to satisfy mutual exclusivity and collective exhaustiveness at each level of clustering.

C. Community Summarization & Indexing

For every identified community in the hierarchy, an LLM parses its constituent nodes, edges, and claims to generate a report-like Community Summary.

  • Leaf-Level Communities: Element summaries are prioritized by overall node prominence and incrementally packed into the context window.
  • Higher-Level Communities: If the sub-network details exceed token capacity, the system ranks sub-communities and recursively swaps out lengthy raw elements for their shorter lower-level summaries.

These summaries act as a pre-computed index that completely maps the corpus's global structure and thematic properties.

3. Theoretical Pillar 2: RAFT (Retrieval-Augmented Fine-Tuning)

While GraphRAG restructures data, RAFT shifts the focus to model alignment. Downstream retrievers are imperfect and introduce noisy or irrelevant text blocks alongside necessary information. RAFT prepares an LLM specifically for this "open-book exam" setting.

A. Training Architecture: Oracle vs. Distractor Contexts

Instead of standard Supervised Fine-Tuning (SFT) or standard RAG, RAFT alters the fine-tuning data mixture using a hyperparameter $P\%$:

  • In $P\%$ of instances: The model is presented with a Question ($Q$), the Golden (Oracle) documents ($D^*$), and several Distractor documents ($D_{i}$) that are completely irrelevant.
  • In $(1-P)\%$ of instances: The model receives the Question ($Q$) and only distractor documents ($D_{i}$), with the golden context entirely omitted.
$$ \text{Training Instance (With Context): } Q + D^* + D_1 + D_2 + \dots + D_k \rightarrow A^* $$ $$ \text{Training Instance (Without Context): } Q + D_1 + D_2 + \dots + D_k \rightarrow A^* $$

This enforces dual optimization: the $(1-P)\%$ slice compels the model to memorize core domain knowledge parameters, while the $P\%$ slice acts as an algorithmic filter, training the model to explicitly ignore misleading distractors.

B. Algorithmic Filtering: Verification via Citations and Chain-of-Thought

To reinforce this filtering capability, RAFT forces the model to generate a structured Chain-of-Thought (CoT) answer. The response must cite verbatim the exact source strings from the reference context within designated identifiers (e.g., ##begin_quote## and ##end_quote##) and spell out the logical steps leading to the final response, preventing overfitting to ungrounded answers.

4. The GRAFT Fusion: How It Operates

GRAFT unifies these two approaches by splitting them across distinct pipeline stages: Offline Fine-Tuning and Online Inference execution.

[Offline Phase]
HotPotQA Subset → Preprocessed with RAFT Receipt (Oracle + Distractors + CoT) → QLoRA Fine-Tuning (Phi-2)

[Inference Phase]
User Query → Cosine Similarity Search over Leiden Community Summaries Index → Top-1 Community Summary Fetched → Structured Prompt Generation → Fine-Tuned Model Execution → Fluent, Globally Aware Response
  • The Offline Alignment: Fine-tuning a base model using parameter-efficient methods like QLoRA (4-bit quantization with Rank $r=32$) on a multi-hop reasoning dataset prepared with the RAFT recipe.
  • The Inference Integration: At query time, GRAFT computes the cosine similarity between the query embedding and the pre-computed embeddings of the Leiden Community Summaries.
  • Context Loading & Generation: The most relevant, high-level community summary (Top $k=1$) is injected into the prompt. The RAFT-aligned model processes this dense snapshot. Because the summary bridges global themes and local relationships, and the fine-tuned model is an expert at filtering relevant details, the system avoids hallucinations.
