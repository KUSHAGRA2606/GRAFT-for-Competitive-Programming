GRAFT

Graph Retrieval-Augmented Fine-Tuning

1. The Core Problem: Vector RAG

Traditional Vector RAG uses text embeddings to fetch facts. However, it struggles with complex tasks:


  • Multi-Hop Reasoning Deficit: Fails to connect disjoint pieces of evidence scattered across independent documents.

  • Global Summarization Bottleneck: Breaks down on "sensemaking" queries that require understanding themes across an entire corpus, rather than isolated facts.

2. Pillar 1: GraphRAG

GRAFT uses a Knowledge Graph Index to solve the global sensemaking limitation.


  • Extraction: An LLM extracts named entities, relationships, and claims from text chunks.

  • Community Detection: The Leiden Algorithm partitions the massive graph into hierarchical, readable communities.

  • Indexing: Every community is summarized into a report. These summaries map the entire global structure of the data.

3. Pillar 2: RAFT

Downstream retrievers often fetch noisy or irrelevant text. RAFT (Retrieval-Augmented Fine-Tuning) prepares an LLM to filter this noise during an "open-book exam".


Training Architecture

RAFT alters the fine-tuning data mixture using a hyperparameter $P\%$:


  • In $P\%$ of instances: The model sees the Question ($Q$), the Golden documents ($D^*$), and completely irrelevant Distractor documents ($D_{i}$).

  • In $(1-P)\%$ of instances: The model sees the Question ($Q$) and only Distractor documents ($D_{i}$).
$$ \text{With Context:} \quad Q + D^* + D_1 + \dots + D_k \rightarrow A^* $$
$$ \text{Without Context:} \quad Q + D_1 + \dots + D_k \rightarrow A^* $$

This dual optimization forces the model to memorize core knowledge while explicitly learning to ignore misleading distractors. It also enforces a structured Chain-of-Thought (CoT) answer with verbatim citations.

4. The GRAFT Fusion

GRAFT unifies these approaches across two pipeline stages:

[Offline Fine-Tuning]

Dataset → RAFT Processing → QLoRA Fine-Tuning (4-bit)
[Online Inference]

User Query → Search Leiden Summaries → Inject Top Summary → Generate Globally Aware Response

5. Implementation Architecture

The GRAFT repository is structured to modularly execute this entire theoretical pipeline:


  • pipeline/phase1/ (Knowledge Extraction): Scrapers targeting Codeforces and CP-Algorithms to build the raw algorithmic text corpus.

  • pipeline/phase2/ (GraphRAG Construction): Extracts entities/claims, builds the graph, runs the Leiden clustering algorithm, and embeds community summaries into a FAISS vector database.

  • pipeline/phase3/ & RAFT/: Generates the synthetic oracle/distractor questions to prepare the dataset for LoRA fine-tuning.

  • src/graft_agent.py (The Brain): A LangGraph state-machine orchestrator. It connects the 4-bit quantized Qwen2.5-3B model (with LoRA adapters) to the FAISS index and a CrossEncoder for sentence reranking at query time.

  • src/app.py: A sleek Streamlit UI providing a real-time, ChatGPT-like interface to the GRAFT Agent.
